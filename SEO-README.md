# Сборка страниц для поиска (Яндекс)

Каталог в `index.html` остаётся единственным источником данных. Claude по-прежнему добавляет карточку и фото — больше ничего делать не нужно. При каждом коммите в `main` GitHub сам запускает `build.mjs` и публикует сайт, в котором есть:

- страница каждой позиции `/lot/<id>/` (фото, характеристики, цена, разметка schema.org Product, «Ещё в разделе»);
- страница каждого раздела `/katalog/<раздел>/` (спецтехника, легковые, грузовики и т. д.);
- `sitemap.xml`, `robots.txt`, `404.html`, `favicon.ico` (из логотипа сайта);
- главная: тот же `index.html`, но с исправленной шапкой (doctype, `lang`, `head`), осмысленным `title`, разметкой Organization и ссылками на разделы и свежие позиции.

Файлы `index.html` и `images/` не меняются: все правки делаются только в собранной копии.

## Как это подключено

1. В корне репозитория лежат `build.mjs`, `site.config.json`, `.gitignore` и `.github/workflows/pages.yml`.
2. В **Settings → Pages** в поле **Source** выбрано **GitHub Actions**, в **Custom domain** указан `izyatka.ru`, включена **Enforce HTTPS**.
3. Результат каждой сборки виден на вкладке **Actions** (workflow «Сборка и публикация сайта»). Запустить сборку вручную можно кнопкой Run workflow.

Если что-то пошло не так, верните в Settings → Pages источник «Deploy from a branch», и сайт будет работать как раньше. Удалять файлы для этого не нужно.

## Как теперь выглядит обновление каталога

1. Claude добавляет фото и карточку в `index.html`, как и раньше.
2. Коммит запускает сборку. Через несколько минут (в сборке участвует около 100 МБ фото) новые страницы появляются на сайте и в `sitemap.xml`.
3. Позицию, которую убрали из каталога, со следующей сборки удаляет и страница; адрес начнёт отвечать 404.

Сборка останавливается с ошибкой, только если каталог в `index.html` перестал быть корректным JSON. Тогда на сайте остаётся предыдущая версия. Мелкие проблемы (нет файла фото, повторяющийся `id`) попадают в предупреждения в логе, сборка при этом продолжается.

## Настройки: `site.config.json`

| Поле | Что указать |
| --- | --- |
| `metrikaId` | Номер счётчика Яндекс Метрики (число). Подключит счётчик и Вебвизор на всех страницах и цели `tg_click` (клик на Telegram), `open_card` (открытие карточки на главной), `lead_form` (заявка отправлена, страница `spasibo.html`). |
| `yandexVerification` | Значение из мета-тега подтверждения прав в Яндекс Вебмастере (только сам код, без тега). |
| `legalName`, `inn`, `address`, `phone`, `email` | Реквизиты и контакты. Выводятся под подвалом каждой страницы и попадают в разметку Organization. Пустые поля не выводятся. |
| `privacyUrl` | Ссылка на политику обработки персональных данных, появится рядом с реквизитами. |
| `homeTitle` | Заголовок (`title`) главной. |

После изменения настроек достаточно сделать коммит: сайт пересоберётся.

## Что сделать дальше

1. Создайте счётчик в Яндекс Метрике, впишите его номер в `metrikaId`.
2. Добавьте сайт в Яндекс Вебмастер, подтвердите права (код — в `yandexVerification`), в разделе «Индексирование → Файлы Sitemap» добавьте `https://izyatka.ru/sitemap.xml`, вручную отправьте на переобход главную и по одной странице каждого раздела.
3. Впишите реквизиты и контакты, добавьте страницу с политикой обработки персональных данных и укажите её в `privacyUrl`.

## Ограничения

- Описания позиций берутся из поля `text`. У большинства позиций хвост текста одинаковый («Изъятая техника лизинговой компании. Быстро оформлю…»), поэтому чем больше уникальных подробностей (комплектация, состояние, история) добавлено в `text`, тем лучше страница будет ранжироваться.
- Для фото нет уменьшенных копий: на страницах разделов картинки грузятся в полном размере (лениво). Уменьшенные превью — хороший следующий шаг.
- Тексты вступлений разделов (`CATEGORIES` в `build.mjs`) короткие и общие; их стоит расширить своими словами.
